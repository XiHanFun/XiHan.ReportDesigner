模型层 core ​

@xihan-report/core 是纯 TypeScript 的模型层：报表定义的类型、校验、取数请求、计算、编辑操作与扩展的合并，不依赖 DOM，浏览器、Node.js 与其它 JavaScript 运行环境里都能用。报表定义的字段见报表定义类型，属性见属性。下表按源码模块列出全部导出。

data-plans ​

名称种类说明

DataRemoval接口删除计划：操作合为一步撤销，cascade 是一并删掉的别处的数目。

planRemoveParameter函数删除报表参数：以它为操作数的筛选条件与引用它的参数绑定一并删掉，最后 removeParameter。
planRenameParameter函数报表参数改名：updateParameter，并把引用它的地方一起改掉——筛选条件的操作数、参数绑定，以及计算字段、公式度量与列汇总公式里的 $名字。

grid ​

名称种类说明
CardPlacement接口新增卡片的位置：写了 x、y 时放在那里并推开压到的卡片，没写时放到第一个放得下的空位。
gridItems函数看板上全部卡片的网格位置，次序与卡片相同。
layoutOperations函数把布局的变化写成一条 layoutCards：before 里有、位置大小变了的卡片；没有变化时为空数组。
NewCard类型待新增的卡片：layout 只需写大小，位置可以留给 planAddCard 找空位。
NewExtensionCard接口待新增的扩展卡片：同 ExtensionCard，layout 只需写大小。
planAddCard函数新增卡片：按 placement 放进网格（推开压到的卡片，缺省整体压实），产出 addCard 与其余卡片的 layoutCards。
planCardLayout函数拖动或改大小：把卡片放到 target（只改写了的项），压到的卡片向下推开，向下拖过下方卡片时两者对调，之后缺省整体压实。
planCompactLayout函数压实布局：每张卡片向上移到碰到别的卡片为止，原本重叠的向下推开；没有变化时为空数组。
planRemoveCard函数删除卡片并清理联动：以它为源的联动整条删除，指向它的目标从联动里去掉，目标删空的联动也删除；之后缺省整体压实。

item-plans ​

名称种类说明
planAddFieldItem函数从数据集字段生成一个列表项并加进列表：维度（查询的 dimensions、交叉表的 rows / columns、分组报表的 groups）取这个字段，日期字段缺省按月分桶；度量里数值字段缺省 sum，其余缺省 count；明细表与分组报表的列只取字段。
planRemoveItem函数删除列表项，并清理对它的引用：以这张卡片为源、在它上面发出取值的联动删除；引用它的直角坐标系列删除，雷达指标与层级从数组里去掉，可选的引用（splitBy、气泡大小与颜色、指标基准值）删掉属性，引用它的迷你图删掉；查询排序的规则与各处的 sort.by 去掉，标注里指向被删系列的去掉。
planRenameField函数字段改名：updateField，并把绑定这个数据集的视图与查询里引用它的地方一起改掉——列、分组、维度与度量的 field，筛选条件与明细排序的 field、目标卡片绑定这个数据集的联动目标的 field，以及同一数据集里计算字段公式对它的引用。
planRenameItem函数列表项改 id：updateItem，并把别处对它的引用一起改掉——图表与指标配置里引用它的字段、查询排序的 key 与维度排序的 by、分组的 sort.by（列）、交叉表维度的 sort.by（度量）、直角坐标图标注的 series，以及以这张卡片为源、在它上面发出取值的联动。

operations/apply ​

名称种类说明
applyOperation函数以纯函数方式执行编辑操作：不修改传入的文档，返回新文档与逆操作数组；没有改到的部分沿用原引用。
applyOperations函数按顺序执行一组编辑操作，整体成功或整体失败（@xihan-ui/designer-kit 的 applyInSequence）；逆操作为各操作逆操作按相反顺序的拼接。

ReportStep接口一步的说明素材。
ReportStepAction类型一步里的动作。
ReportStepKind类型一步改的对象种类，与设计器文案 objectKinds 的键同一组。

operations/types ​

名称种类说明
AddCardOperation接口新增卡片，index 缺省放在末尾；位置大小写在卡片的 layout 里。
AddDatasetOperation接口新增数据集，index 缺省放在末尾。

ItemOwner接口列表项的所在：card 缺省时是报表主体的视图；表格卡片是它的视图，图表与指标卡片是它的查询，series 是直角坐标图的配置。
LayoutCardsOperation接口一次改多张卡片的位置大小。
MoveDatasetOperation接口把数据集移到 index。
MoveFieldOperation接口把数据集里的字段移到 index。

RemoveCardOperation接口删除卡片；引用它的联动不随之改动，用 planRemoveCard 一并清理。
RemoveDatasetOperation接口删除数据集；用着它的卡片、视图与联动不一并改，要连带删除时用 planRemoveDataset。
RemoveFieldOperation接口删除数据集里的字段；引用它的地方不一并改，要连带删除时用 planRemoveField。
RemoveItemOperation接口删除报表主体或卡片里某个列表的一项。
RemoveLinkOperation接口删除看板的联动。
RemoveParameterOperation接口删除报表参数；引用它的地方不一并改，要连带删除时用 planRemoveParameter。
ReplaceDocumentOperation接口整份换掉报表定义，如编辑整份 JSON 之后应用。
ReportOperation类型编辑操作。
ReportOperationResult类型操作结果，即 @xihan-ui/designer-kit 的 OperationResult：新文档，以及按顺序作用于新文档即可还原出传入文档的逆操作。
ReportOperationType类型编辑操作的种类。
ReportPath类型报表里的路径：字符串段是对象的属性名，或数组里带 id（没有 id 时取 name）的那一项；数字段是数组下标。
SetBodyOperation接口换掉报表主体，用来改报表的类型。
UpdateCardOperation接口修改卡片；不能修改 id、kind 与 layout（位置大小用 layoutCards）。
UpdateDashboardOperation接口修改看板本身（网格）；不能修改 type、cards 与 links。
UpdateDatasetOperation接口修改数据集；不能修改 id 与 fields（字段用字段的操作）。
UpdateDocumentOperation接口修改文档本身的属性；不能修改 schemaVersion、datasets、parameters 与 body。
UpdateFieldOperation接口修改字段；可以改 name，同一数据集里不能重名。
UpdateItemOperation接口修改列表项；可以改 id，同一列表里不能重复。
UpdateLinkOperation接口修改联动；不能修改 id。
UpdateParameterOperation接口修改报表参数；可以改 name，不能与别的参数重名。
UpdateViewOperation接口修改视图：card 缺省时是报表主体（须是明细表、分组报表或交叉表），否则是那张表格卡片的视图；不能修改 type。
