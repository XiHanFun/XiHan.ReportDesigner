# XiHan.ReportDesigner 测试审查

## 判断标准

每个用例给出「保留、改写、合并或删除」的结论，并说明它保护的可观察契约。

- 保留：缺陷复发时会失败，覆盖报表定义的校验与问题码、参数、取数请求、计算结果、编辑操作与撤销、元素的公开属性 / 事件 / 方法、扩展登记与合并查重、语言包或导出的文件内容。
- 改写：只复述实现、mock 后证明 mock、断言私有字段、依赖脆弱的 DOM 顺序或用固定延时碰运气。
- 合并：与相邻用例输入和断言等价，没有提供新的失败定位。
- 删除：不可能失败、只验证常量或快照自身，或已被更清楚的用例覆盖。

## 本仓专项

- 用例在各包的 `tests/*.spec.ts`。core 的跑在 Node 里、不碰 DOM；runtime、designer 里要 DOM 的在文件头写 `// @vitest-environment jsdom`，纯计算的不写。
- 计算类用例的期望值要能手算：几行固定数据，断言具体数值、表头与行列顺序；不拿实现自己算出的结果当期望，不用大快照。涉及聚合或透视的，看明细行（`kind: 'rows'`）与汇总行（`kind: 'aggregated'`）两条路是否都覆盖到，只测了一条的标出来。
- 编辑操作要核「执行再撤销回到原状态」；校验要核非法输入给出的问题码与 `path`。
- jsdom 证明不了真实布局、计算样式、拖动与图表绘制，这类结论到 playground（`report/` 下 `pnpm dev`）或文档站的真实浏览器里核，不在 jsdom 里断言像素。
- 比较 DOM 元素的顺序时比文字或 id：`toEqual` 对 DOM 元素按结构比，同样的空元素换了顺序也算相等。
- 设计器包的单条超时上限写在 `report/packages/designer/vitest.config.ts`（约为本机最慢一条的十倍）；用例变慢先查原因，不靠继续加大上限。
- 假定时钟只在控制时间的用例里启用（如自动保存），并在 `afterEach` 还原；用到 localStorage 的用例结束时清掉自己写的键。
- 文档站的 `pnpm check:examples` 只检查示例报表能算出来、不核数值，不能代替 core 的计算用例。

输出按风险排序，附文件与行号。除非用户要求运行，否则以静态审查为主；不因缺少新测试自动修改代码。
